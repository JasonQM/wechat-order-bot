# 微信群加油订单自动报价

盯微信群里的加油机照片，读出金额，按 95 折算价，带收款码回给客户。

面向的场景很具体：加油站/油品销售在微信群里接单，客户拍一张加油机显示屏的照片，
需要人工算折扣、报金额、发收款码。这个工具把这三步自动化。

## 工作方式

**纯外部屏幕感知** —— 抓微信窗口的截图，OCR 读屏，模拟鼠标点击和键盘输入。
不注入微信进程、不 hook 消息、不走协议层。

这个选择是刻意的。协议层方案（WeChatFerry / PadLocal 等）能力更强，但：
- 有的已停止维护、不支持微信 4.x
- 有的需要改客户端或注入 DLL，属于客户端特征异常，封号风险高
- 而封号对生意是灾难性的，不是"重装一下"能解决的事

代价也很清楚：**读不到消息 ID、读不到未读数**，只能靠"屏幕上看得见什么"来判断。
这一点决定了下面很多设计，也是这个项目所有坑的来源。

## 快速开始

环境：**Windows 10/11 + 微信 PC 版 4.x + Python 3.10+**
（窗口抓图和按键模拟都依赖 Win32 API，跑不了 macOS / Linux）

```bash
python -m pip install -r requirements.txt
```

首次运行 RapidOCR 会下载约 15MB 的 ONNX 模型，需联网一次，之后可离线。

### 1. 填配置

```bat
copy config\app.example.json config\app.json
copy config\groups.example.json config\groups.json
```

然后编辑 `config/app.json`，至少填上：

| 配置项 | 说明 |
|---|---|
| `vision.api_key` | 云端视觉模型的 Key（可选，只走本地识别可以不填） |
| `ocr_space.api_key` | OCR.Space 的 Key（可选，本地读不出时的兜底） |
| `reply.image` | 收款码图片的路径，自己放一张到 `assets/` |

`config/groups.json` 里填要回复的群名，或者在 Web 面板的「群管理」页可视化添加。

> 这两个真实配置文件都在 `.gitignore` 里 —— 里面有密钥、客户群名和你的收款码。

### 2. 体检

```bash
python src/main.py doctor
```

会逐项检查：微信窗口能不能找到、抓图是否正常、OCR 引擎是否可用、视觉模型通不通。

### 3. 试跑一轮

```bash
python src/main.py once
```

默认是**安全模式**：只识别、只落库，不发消息。确认识别结果没问题再加 `--send`。

### 4. 常驻

```bat
start_bot.bat
```

窗口开着就是在跑，关掉就是停。同一时刻只会有一个实例（命名互斥体保护）。

### 5. 数据面板

```bat
start_web.bat
```

打开 http://127.0.0.1:8080 ，可以看到订单记录、待人工处理、群管理、回复模板，
右上角能启动/暂停/停止机器人。

## 识别是怎么做的

两条通道，都通过才算数：

**本地（主力）**：OpenCV 找加油机的 LCD 面板（Canny + 四边形检测）→ 透视矫正
→ 光照归一化 → 按行切分 → 七段数码管逐字符识别 → 多组参数投票。
不联网、约 3-4 秒。

**在线（兜底）**：本地读不出时把整图发给 OCR.Space（Engine3 + 中文），
按「金额/油量/单价」标签抠数字，再用 `金额 ÷ 单价 = 油量` 做代数校验。

最后还有一道**算术闭环**：`油量 × 单价` 必须等于 `金额`（容差 0.05%）。
对不上就转人工，绝不硬发。

## 目录

```
src/            机器人主体
  window.py       窗口枚举、PrintWindow 抓图、后台投递点击/按键
  desktop.py      侧边栏扫描、切群、滚动、布局计算
  perceive.py     截图 → 气泡序列（文字/图片/分界线）
  imgcap.py       点开图片、抓预览窗、后台关窗
  local_reader.py 本地七段数字识别
  ocr_space.py    OCR.Space 兜底
  recognize.py    识别编排
  pricing.py      算价（整数「分」运算）
  sender.py       发送文本/图片/@
  scheduler.py    主循环：扫描 → 判重 → 识别 → 回复 → 落库
  single_instance.py  命名互斥体单实例保护
web/            数据面板（Flask + SQLite）
config/         配置
data/           运行时数据（订单库、截图，不进版本库）
tools/          诊断脚本
```

## 几个绕不开的限制

这些不是"以后优化"，是屏幕感知方案的固有边界。让客户重发原图通常比改代码有效。

- **图片必须够清晰。** 微信预览窗抓的原图约 1700px，能读；退化到聊天区缩略图
  （300px 左右）就基本读不出来，会转人工。
- **同一张照片发两次，只会回一次。** 系统无法区分"客户重发催单"和"同一条消息扫了两遍"，
  默认按重复处理（避免重复报价收两次钱）。漏了可以在面板点「交回机器人重试」。
- **窗口被遮挡或最小化时抓图会失败**，这一轮跳过，下一轮重试。
- **群名会被侧边栏截断**，所以切群用白名单里的完整名字，不用屏幕上读到的那串。
- **手机版/网页版微信不适用**，只认 PC 版窗口。
